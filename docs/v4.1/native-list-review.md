# 4.1 原生列表实现 Review 与修复

日期：2026-10-29。对应 T03—T05、T13、T14。源码范围：NetdiskOutlineView、DirectoryBrowserState、NetdiskFilesView。

## 已修复

| 发现 | 修复 |
| --- | --- |
| SwiftUI 重复 updateNSView 会反复建立尚未触发的 Observation 追踪 | updateInput 仅更新动作、能力和标记；业务变化由一次性追踪重建快照。转存标记变化只重绘，保持单条活动追踪 |
| 无障碍查询展开能力时 shouldExpandItem 带业务副作用 | shouldExpand／shouldCollapse 只返回权限；实际展开通知更新模型并加载，收起通知清理隐藏子选；程序恢复时沿用模型状态 |
| 重试按钮依赖 clickedRow，键盘／VoiceOver 激活时可能命中旧行 | 按钮直接弱引用对应节点，动作按节点启动加载 |
| 刷新时显示可接收拖放，随后上传上下文拦截而吞掉操作 | 原生目标校验读取当前上传能力；acceptDrop 返回业务回调的实际接收结果 |
| 换树刷新后普通行焦点丢失 | 目录状态保存对象引用和行位置，按引用恢复，消失后选择最近可见真实条目；导航或换账号清理 |
| 日期／大小直接使用 NSTextField，文字贴近行顶部 | 使用 NSTableCellView 包装并居中约束，和名称行对齐 |
| 空勾选框像禁用控件 | 使用清晰的 square／checkmark.square.fill 图标，保持 checkbox 辅助语义、选择状态和继承说明 |
| 名称列自动填充可能覆盖用户拖动宽度 | 原生表格采用 noColumnAutoresizing，关闭 outline 列按内容自动调整；用户拖动保存列宽与视口锚点，窗口宽度始终相对锚点计算 |

## 资源与状态检查

- 观察及单元格回调弱引用协调器；拆除时取消加载任务、失效观察代次、清理缓存并解除代理。
- 快照递归仅深入已展开的加载子树，收起缓存的深层目录留待再次展开时访问。
- 程序展开恢复只重建可见状态，网络加载由实际用户展开或重试触发。
- 视口回调只在宽度实际变化时执行，列拖动沿用原生 header；列宽与当时视口组成稳定用户锚点。程序调整标记隔离原生回调，窗口临时窄布局的最小宽度限制保持局部，恢复宽度按原锚点计算。
- 文件页空目录／搜索空结果使用 SwiftUI 投放区域；原生列表区域由 AppKit 单独管理拖放与表头事件，清理覆盖整个列表的重复投放包装及遗留 dropEntry 状态。
- 刷新时只取得并排序一次根节点，快照与子树收集复用该结果；准确焦点存在时惰性跳过备用行扫描与数组构造，保持原生命周期和选择规则。
- 上述计算清理按 macOS 14 目标完成全 App Debug 静态类型检查，日志 `/tmp/ferry-v41-list-computation-typecheck.log`；单元格创建方式保持原实现，资源趋势沿用实际运行记录。

## 验证

- 三个 Swift 文件语法解析通过，相关文件差异检查通过。
- 主代理已在实际 App 发现并提供日期基线、勾选外观、辅助功能自动展开、列拖动证据，本轮修复承接这些发现。
- 实际 App 已验证辅助功能读取保持目录状态、日期和名称居中、空勾选框轮廓及样本目录双击进入。
- 列拖动根因是覆盖原生列表的 SwiftUI dropDestination 包装。移除后主代理实际拖动两条列边界，名称宽度从 270 变为 185.5 点，日期宽度从 200 变为 170 点，表头与行同步；临时原生表头诊断的处理前后宽度与轨迹一致，证据位于本机 `/tmp/ferry-v41-ui.log`。
- 诊断结束后恢复默认原生表头，移除临时日志与局部事件观察；已验证的列调整机制保持。
- 文件搜索按当前可用宽度在 160—220 点间调整，窄窗省去固定间隔。实际 toolbar 控件在 110 点宽时仅有 74 点文字区，小于占位文本的 77.393 点；160 点宽时文字区为 124 点，838 点宽侧栏显示截图已确认占位文本完整。后续缩窗与焦点验证见[搜索尺寸记录](search-sizing-implementation.md)。
- 半屏刷新／切页发现增量列宽算法会累计最小宽度裁剪偏差。本轮改为 `锚点名称宽度 + 当前视口 - 锚点视口`，用户拖动时保存锚点，程序布局沿用锚点；等待重建验证窄宽往返及刷新恢复。
- 其他 C08—C17、C44—C45 子场景按统一执行记录继续验收。
