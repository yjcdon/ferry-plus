# 4.1 Core 实现审查与证据范围

日期：2026-10-29。审查基线：`31077ec` 至 `1a583a7` 的 Core 差异；本记录仅描述此次审查范围。归档、分页及调用方源码已核对，功能验收子场景见下表。

## 审查结论

本轮 Core 变化集中在历史依据自动归档和上传文件分页。现有任务、文件、凭据及设置的编码格式沿用原约定。

| 范围 | 源码位置 | 核对结果 |
| --- | --- | --- |
| 历史依据写入 | `DownloadIntegrityArchive.swift:9—18` | 按任务 UUID 保存，使用现有 IntegrityManifest 格式，原子写入后读回确认；只保存比对依据 |
| 移除前准备 | `JobCoordinator.swift:589—624` | 停止任务及引擎、合并实际完成位置、持久化后归档 |
| 移除提交 | `JobCoordinator.swift:625—635`、`739—746` | 归档后校对取消和当前依据；保存任务列表失败时恢复原任务；原件清理在移除提交后执行 |
| 正常退出 | `JobCoordinator.swift:429—440` | 退出等待正在进行的移除操作收尾 |
| 上传分页 | `UploadStore.swift:67—73`、`104—122` | 每页读取一次权威 manifest，最多 500 项，按成员顺序读取并检查取消、文件身份与账号 |
| 分页调用方 | `UploadCoordinator.swift:130—132`、`UploadListView.swift:428—468` | 业务 API 委托存储分页；界面按请求代次、账号与取消状态发布结果 |

归档为按需执行的有限磁盘操作，调用方等待完成；最大清单大小为 4 MiB、最多 10000 条。分页仅保留当前页文件，界面按状态变化刷新。相关实现采用有限遍历和既有 actor 生命周期，无新增持续轮询、常驻计时器或执行自旋。运行资源的完整版本对比由 C49 单独记录。
