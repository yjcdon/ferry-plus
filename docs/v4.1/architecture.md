# Ferry Plus 4.1 技术方案

状态：设计阶段，待实施。日期：2026-10-29。

依据：[产品方案](product-proposal.md)。源码核对基线：`31077ec`，分支 `codex/v4.1-hig-design`，功能基线为 4.0。本文描述目标实现；运行结果在实施阶段记录。

## 1. 技术结论

保留 SwiftUI 主窗口与 FerryCore 传输、账号和网盘服务。文件工作区采用 `NSOutlineView` 原生列模型承载树形列表，以原型验收作为迁移门槛。上传、下载共用展示结构和筛选结果，业务状态继续由现有协调器管理。

应用自有界面统一使用不透明实色背景、轻分隔线、标准图标和系统字体。用户明确要求不使用 Liquid Glass。HIG 指导布局、焦点和交互，视觉材料按此产品要求实现。

支持 Apple Silicon、macOS 14 及以上。沿用账号、凭据、任务、目录、设置和完整性数据格式。百度安全覆盖、夸克保留两份／跳过继续使用现有能力。

## 5. 关键设计

### 5.1 原生树形表格

以 NSViewRepresentable 封装 NSScrollView 和 NSOutlineView。名称、修改日期、大小对应三个 NSTableColumn；名称单元格容纳勾选框、图标、名称和已有标记，展开控件由原生树表处理。表头与行由同一列模型管理。

- 名称列吸收窗口剩余空间，日期、大小保持用户宽度；允许列宽调整，固定列顺序。
- 整列表头触发排序，分隔线命中区优先拖动。排序事件写回 DirectoryBrowserState，沿用同级文件夹优先及稳定次序。
- 列宽保存为两家共用的工作区 UI 偏好；分享页独立。显式保存宽度，关闭原生 autosaveTableColumns，排序状态继续由目录模型管理。
- 日期初始宽度按完整时间测量，名称设置可读最小宽度；窄至各列最小宽度之和时启用水平滚动。原型确定具体初始尺寸并记录。
- 日期使用本地时区、固定 `yyyy-MM-dd HH:mm:ss` 格式和等宽数字。缺失日期、文件夹大小显示“—”。长名称中间省略、悬停显示全名。

异步更新流程：

1. 数据源同步返回已加载子项。展开未加载目录时显示加载占位，启动现有节点加载。
2. 观察已显示节点的子项、加载、展开和勾选变化。真实条目按稳定引用标识；加载／重试占位使用独立标识，只参与展示和辅助功能。
3. 结果校对树实例、目录代次和账号会话后更新子树。收起后完成的请求可缓存于有效节点；切目录、账号或销毁视图时清理适配器观察和任务。
4. 刷新沿用目录模型的展开与勾选快照。仍存在的焦点恢复；被删除或搜索排除时聚焦最近可见位置。
5. 新建／重命名后的定位改为带标识的一次性请求，适配器滚动、聚焦后确认消费，保证模型和原生视图的时序。

父选包含子项，子项显示继承选择，继续支持展开和双击。行焦点独立于勾选；空格操作焦点项的有效勾选，继承子项保持父选语义。批量命令读取有效勾选集合。右键已勾选项使用该集合；右键其他项以该项为目标并保留原勾选。重命名要求单个有效目标。

收起目录调用现有 discardDescendantSelection，清理隐藏子项的独立勾选，保留父项勾选。当前目录搜索只显示本层匹配条目，搜索期间收起树展示并暂停展开；查询变化沿用 pruneInvisibleSelection 清理不可见选择。清空搜索后恢复正常树浏览。分享页保留自身的选择和展开规则。

拖入文件夹行以上传至该目录，拖入其他行或空白以上传至当前目录；确认面板冻结账号、会话、目录和本地文件。安全访问权限沿用上传面板与任务的交接流程。

原型覆盖异步展开、勾选继承、整列表头、列边界、右键、拖放与 VoiceOver。通过后替换 NetdiskFilesView。分享页继续沿用 FileTreeRow 和初始全选语义，执行共享模型回归。

### 5.2 窗口、导航与筛选

保留 NavigationSplitView。详情保存“期望展开”和“用户宽度”，实际显示由空间计算；缩窄保持用户偏好。详情宽度上限为主窗口内容宽度一半，主列表保留可用空间。半屏不足时收起详情并保留工具栏入口。窗口、侧栏用原生恢复能力，详情沿用场景键，恢复按当前屏幕裁剪。

替换 MainView 当前 820／960 点的固定窗口最小宽度。原型按实际屏幕逻辑尺寸确定可用最小宽度，同时验证侧栏收起、工具栏收纳、详情收起和表格横向滚动。例如 1440 点宽屏幕的半屏约为 720 点，验收需在真实半屏尺寸完成。

传输集合：全部任务 → 网盘／方向／搜索 → 状态分类 → visibleItems。分类数量使用分类之前的集合；列表、底部统计、全选、批量操作使用 visibleItems。下载方向只展示下载汇总，上传同理，全部方向展示两者。未知总量沿用已知字节与真实活动状态。

命令执行时重新求交当前可见标识与动作能力。切换范围清理不可见任务选择。“查看全部”清除网盘范围，保留方向、分类和搜索。范围浅强调，当前页强选中，辅助功能提供文本含义。

### 5.3 工具栏、搜索与实色外观

复用 TaskSearchField 的 NSSearchField、清除和焦点请求。操作组与搜索独立布置，搜索宽度随可用空间变化，紧凑窗口通过系统收纳保留入口。⌘F 聚焦当前页搜索；目录搜索和传输搜索各自维护。

应用自有工具栏、侧栏、主内容、详情、sheet 和设置采用不透明语义背景色。macOS 26 的工具栏自动共享背景通过公开且受版本判断保护的 API 隐藏，再使用实色容器；macOS 14 使用标准实色外观。具体 API 在原型编译及截图验收后固定。标准图标、焦点环和按钮操作保持系统行为。

在系统默认透明度设置下，以后方彩色窗口检查透出情况。系统文件选择器和服务方登录网页由系统或服务方绘制，应用自有容器执行实色要求。使用公开 API，保持正常标题栏行为。

### 5.4 统一任务行与详情

新增轻量展示值，从 Job、UploadJob 计算名称、用户状态、进度、辅助信息与可用动作。真实状态和持久化仍由协调器负责。

| 业务情况 | 用户展示 | 操作依据 |
| --- | --- | --- |
| 准备、排队 | 正在准备、等待中 | 当前动作能力 |
| 数据传输 | 正在下载／上传、字节及有效速度 | 现有暂停、取消等能力 |
| 暂停 | 已暂停、继续入口 | 暂停标记及真实阶段 |
| 上传 committing/verifying/publishing（合并、检查、发布） | 正在完成、活动指示 | 保留阶段能力与结果核对 |
| 成功 | 已完成、大小 | 查看位置、移除 |
| 跳过、取消 | 已跳过、已取消 | 沿用原分类与操作能力 |
| 失败、部分失败 | 原因、失败数量／查看入口 | 现有重试或结果核对 |

远端写入结果待核对时沿用 reconcile 流程，保留“重试”与“核对结果”的区别。重复任务关联、重选本地源文件、发布备份定位均承接到统一详情。

上传下载共用行布局，保留 TransferTaskID 的方向与 UUID 联合身份。动态高度稳定后，通过实际选择、滚动、裁剪验证决定清理 rowLayoutID 重建补丁。上传详情 sheet 迁入右侧详情；多选展示数量和共同动作。下载双击 Finder 等既有行为继续保留。

历史手动摘要 UI 清理先迁移数据流程：移除下载任务前，将现有 removalIntegrityManifest 结果保存到 App Support 专用归档目录，按任务 ID 原子写入，读回比对后传入现有 exportedManifest 分支。归档文件使用现有 IntegrityManifest 格式，路径由存储层管理。精确绑定对象的已验证记录继续进入 integrityStore。

IntegrityManifest 仅保存相对路径、大小、算法和摘要，属于比对依据。verified／pending／mismatch 状态在存续任务中保持原义；已验证结论只由现有精确对象归档规则生成。保存失败保留任务和文件，提供简短重试；并发变化由移除前的现有比对校验。重试沿用稳定任务标识。升级和降级保留归档目录。迁移完成后清理手动校验 sheet、导出选择器和专用包装；维护时可读取归档。

### 5.5 面板、输入与反馈

沿用下载、上传的冻结目标对象；新建、重命名、回收站确认采用相同的账号／会话／目录快照。提交前及回调后校对上下文，登录变化时重新登录并确认目标。同类面板复用布局与字段反馈，各业务保留提交函数。

本地文件选择使用系统面板，取消后保留已有项目；临时访问权限在提交交接或关闭时释放。上传预检查随输入自动更新，结果按请求代次匹配。名称规则复用两家现有校验器，提交后非法输入红框和简短提示；编辑后更新反馈，成功后关闭。

成功消息带唯一标识，替换后重新计时，关闭或离页取消计时，最长 10 秒消失。可处理错误保留至处理、关闭或上下文变化。页面持有局部反馈，任务错误沿用任务记录。加载、空目录和搜索空结果分别表达。

### 5.6 设置、键盘与存储

四类设置继续绑定 FerrySettings，增加上次分类的 UI 偏好。专业参数整理到高级区域，沿用原字段与行为。两家账号使用相同字段顺序和操作位置，凭据仍由现有账号与钥匙串服务管理。

命令随焦点派发：输入框编辑文本，列表处理方向键、空格与目录导航；⌘F 搜索、⌘, 设置、Escape 取消。破坏性操作保留明确确认。VoiceOver 提供名称、层级、勾选／继承状态、排序方向和动作名。

新增文件列宽、设置分类使用独立版本化 UI 键，已有页面、目录、详情偏好继续沿用。恢复尺寸按控件合法范围处理。任务与凭据 schema 继承 4.0，内部历史依据归档为增量文件。发布任务统一调整版本与分发配置。

## 6. 迁移清理与验证

| 替代项 | 清理条件 |
| --- | --- |
| 文件表头与列拖动 | NetdiskFilesView 原生替换通过，清理该页手动宽度与布局 |
| FileTreeRow | 保留分享页及递归调用，回归其默认全选 |
| WidthResizeHandle | 移除文件列调用，保留详情调用 |
| 重复任务行 | 共用布局承接两方向状态与动作后清理 |
| UploadDetail sheet | 文件重选、云端定位、核对结果全部迁移后清理 |
| 历史手动检查和导出 UI | 本地归档及旧数据回归通过后清理入口和包装 |
| 分散统计 | 全部调用使用同一筛选结果 |

实施顺序为原型、调用方迁移、验证、清理。原型遇到交互阻塞，先修订方案再替换现有列表。编译和已有测试用于实现检查，真实 App 验证双网盘浏览、管理与上传下载。写入证据记录对象、账号、结果与内容摘要，验收时逐项复核。

资源比较使用同设备、构建模式、目录及任务样本，记录包体、空闲 CPU、内存和操作表现。异常增长先定位再评估交付。详细步骤见[任务清单](tasks.md)和[测试用例](test-cases.md)。
