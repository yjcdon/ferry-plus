# 4.1 原生搜索框尺寸修复

日期：2026-10-29。关联 T07、T13，C01、C20—C22。

## 根因与修复

文件工具栏原先允许搜索框缩至 110 点。实际工具栏中的 NSSearchField 使用 controlSize 原始值 4、13 点系统字体，其内距与无窗口默认控件不同。对同一实际控件测量：

| 项目 | 宽度 |
| --- | --- |
| 【搜索当前目录】按实际字体测量 | 77.393 点 |
| 控件宽 110 点时的 searchTextRect | 74 点 |
| 控件宽 140 点时的 searchTextRect | 104 点 |
| 控件宽 160 点时的 searchTextRect | 124 点 |

原 110 点控件的文字区域比占位文本少 3.393 点，导致右端裁切。两处搜索入口改为共用 TaskSearchField.minimumWidth 160 点：文件搜索在 160—220 点间调整，传输搜索在 160—240 点间调整；sizeThatFits 使用相同下限，保留原生字号、图标、清除与焦点行为。

搜索与操作继续独立分组。文件内容区小于 700 点时，工具栏保留上传、下载和独立搜索，新建文件夹、移到回收站与刷新进入文字【操作】菜单。较宽窗口继续平铺五个操作。两种展示共用同一操作目标和启用条件；传输内容区小于 700 点时省去额外固定分组间隔，主窗口总体最小宽度保持 640 点。

## 验证

实际工具栏控件 frame 与 bounds 均为 160 × 36 点。838 点宽、侧栏显示时，截图完整显示【搜索当前目录】；随后 736 点半屏发现五个平铺操作挤掉整个搜索项，因此继续加入上述窄窗菜单规则。窗口诊断同时确认 contentMinSize 为 640 × 452 点，当前原生表格与内容的 fittingSize 未产生横向最小宽度。

修改文件语法解析及完整 App 源码快照的 macOS 14 目标类型检查通过。测量使用的临时诊断文件及主窗口挂钩已清理，文件移入废纸篓。无诊断版本的缩窗、搜索输入、清除和传输搜索由主代理最终整合构建验收。
