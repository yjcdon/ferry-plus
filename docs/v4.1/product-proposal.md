# Ferry Plus 4.1 产品方案：整体 macOS 交互优化

状态：方案阶段。日期：2026-10-29。发布基线：[Ferry Plus 4.0](https://github.com/yjcdon/ferry-plus/releases/tag/v4.0)。

## 1. 目标与继承关系

让 Ferry Plus 保持 Ferry 的简洁、轻量，同时具备一致、顺手的 Mac 文件管理与传输体验。

本版承接 [4.0 文件工作区](../v4/product-proposal.md)，覆盖整个 App：主窗口、侧边栏、文件列表、工具栏、搜索、传输列表、详情、确认面板、账号、设置、反馈、键盘操作与可访问性。下文是基于苹果 HIG 和现有业务作出的产品设计；控件选择由技术验证确定。

适用范围：Apple Silicon、macOS 14 及以上，百度与夸克各一个同时登录的账号。沿用独立 App、ZIP 和 Homebrew 分发。保留现有登录状态、任务历史、设置和传输数据兼容。

功能基线包括双网盘浏览、分享下载、账号内下载、本地上传、目录上传、新建文件夹、重命名、移入回收站、批量操作和后台内容检查。夸克同名处理沿用保留两份与跳过，百度沿用安全覆盖。后续网盘能力扩展另行规划。

## 2. 当前问题与解决方法

| 当前问题 | 解决方法 | 用户得到的结果 |
| --- | --- | --- |
| 文件页、上传行、下载行、详情的信息布局各有一套 | 按用户任务统一视觉与信息层级 | 同一种操作在各处具有相同含义和位置 |
| 文件表头、列宽和行尾依赖手动协调，经历多轮拖动修复 | 优先验证系统树形表格，让同一套列模型负责表头和内容 | 排序、列宽和滚动稳定，减少维护点 |
| 网盘范围和传输页面使用相同强度的高亮 | 分别表达范围与当前位置 | 清楚当前查看哪家网盘的哪类任务 |
| 上传任务集中展示多个内部处理阶段和统计 | 主列表展示结果与必要进度，明细集中到详情 | 一眼看懂任务进度与下一步操作 |
| 确认、提示、设置仍存在文字和布局差异 | 按场景统一面板与反馈规则 | 更少阅读负担，更顺畅的操作流程 |

## 3. 主窗口与导航

### 3.1 窗口骨架

主窗口采用左侧导航、中间内容、右侧任务详情的结构。文件页以目录和文件为中心；传输页以任务为中心。主标题保持简短：文件页显示网盘名称，传输页显示当前分类及必要范围。

- 侧边栏可调整宽度、可隐藏，恢复时保留用户设置。
- 任务详情可开关、可调整宽度，最大占主窗口一半；选中任务变化时同步详情。
- 窗口变窄时优先保留主内容空间，详情栏按空间收起并保留恢复入口；空间恢复后尊重用户的展开偏好。
- 记住窗口、侧边栏和详情栏宽度，按当前屏幕可用范围恢复。
- 普通窗口、半屏和全屏均保持文件名称、主操作和搜索可用。

### 3.2 侧边栏与传输范围

沿用“网盘／传输／账号与设置”的结构。百度、夸克保留真实品牌图标，传输分类采用系统图标。

- 当前页面采用系统选中背景。
- 查看单家传输时，对应网盘保留较浅的强调背景，表达当前范围；当前传输分类使用完整选中背景。
- “查看全部”恢复两家网盘的传输范围，并保留当前方向和状态分类。
- 全部、进行中、已完成、失败继续作为传输分类；全部传输、下载、上传继续作为方向切换。
- 分类数量、可见任务与批量操作共用筛选规则；底部汇总明确反映当前展示范围。
- 账号与设置保留底部入口，账号名称集中在账号菜单和账号设置中展示。

此处高亮强度属于 Ferry Plus 的设计选择，需用实际界面确认范围与当前位置都能清楚辨认。

## 4. 文件工作区

### 4.1 树形列表

保留名称、修改日期、大小三列和现有勾选方式。表头、文件行和列边界形成完整列表。

- 层级缩进集中在名称列，日期及大小在各层保持对齐。
- 点击整列表头切换排序，重复点击反转方向；排序按每层同级条目执行，文件夹优先。
- 拖动列边界时，表头与所有文件行同步；保存用户列宽偏好。
- 日期使用 `yyyy-MM-dd HH:mm:ss`，数字等宽；大小右对齐；文件夹大小显示“—”。
- 长文件名使用中间省略，悬停展示完整名称。
- 收紧表头和行的留白，使用轻分隔线；名称优先获得宽度。
- 目录加载、刷新、排序后保留仍有效的展开与选择状态。
- 文件列表底部保持“已选 N 项”。

### 4.2 浏览、选择与拖放

- 箭头展开或收起目录；双击名称或图标进入文件夹；路径栏提供逐级定位与返回上级。
- 勾选框负责批量操作。父目录选中代表整个目录，子项显示继承的选中标记，仍可继续浏览。
- 原生行焦点用于键盘导航，勾选集合用于批量命令，二者在视觉与操作上明确区分。
- 拖入空白区域上传到当前目录；拖到文件夹行时高亮该目录，确认面板展示最终目标。
- 文件操作继续使用上传、下载、新建文件夹、重命名和移到回收站；右键菜单与工具栏使用一致命名及范围。
- 文件搜索沿用当前目录名称筛选，切换网盘与目录遵循现有选择清理规则。

### 4.3 控件方案与迁移成本

优先评估系统原生树形表格，由统一列模型处理表头、列宽、滚动、排序入口与行布局。SwiftUI 继续负责主窗口和业务页面；具体表格可评估原生 AppKit 承载。

原型必须覆盖异步展开、勾选及继承选择、完整列头点击、双击进入、右键范围、拖入上传、窄窗口、VoiceOver。通过这些验证后再替换现有列表。此项涉及共享文件树及分享选择页的调用关系，是本版主要实施成本。

HIG 约束的是交互效果。代码组件的拆分依据职责与复用确定，最终界面呈现为一体化列表。

## 5. 工具栏与搜索

| 页面 | 分组 |
| --- | --- |
| 文件页 | 上传、下载、新建、删除、刷新组成操作组；搜索独立位于右侧 |
| 传输页 | 分享链接组；开始／暂停与详情组；右侧搜索组 |

采用系统按钮、标准图标、实色背景和系统焦点表现。窗口空间变化时使用系统工具栏收纳能力，保持常用操作和搜索可达。

搜索框统一高度，宽度随窗口适配；文件页显示“搜索当前目录”，传输页显示“搜索任务”。输入后筛选，清空后恢复。`⌘F` 聚焦，保留系统清除按钮和蓝色焦点框。搜索范围与页面语义一致。

## 6. 传输列表与任务详情

### 6.1 统一上传、下载任务行

两种任务采用相同的信息顺序、字号和布局：

```text
文件名或任务名                         暂停／重试
进度条
正在上传 · 25 MB / 100 MB · 8 MB/s
```

- 全部网盘视图展示来源网盘；单家视图利用导航范围表达来源。
- 进行中展示状态、字节进度及速度；暂停任务显示“已暂停”和继续入口。
- 已完成展示结果和大小，失败展示简短原因及重试入口。
- 上传合并、内容检查和发布阶段统一表达为“正在完成”；后台继续完整处理，成功后进入已完成。
- 待收尾时用状态和适当的活动指示表达实际工作，传输字节达到总量仍保留收尾状态。
- 批次文件数量、详细路径和来源账号集中到详情；部分失败展示可处理的失败数量与查看入口。
- 移除任务、删除本地下载文件、删除云端对象具有各自明确的操作名称和范围。

### 6.2 紧凑详情面板

| 区域 | 内容 |
| --- | --- |
| 任务概况 | 名称、状态、大小；进行中补充速度和剩余时间 |
| 来源与位置 | 网盘、必要的来源账号、本地和云端位置、分享链接 |
| 文件明细 | 批次内文件、状态和异常原因 |

主要操作固定在底部，如在 Finder 中显示、在网盘中显示、继续或重试。完成任务省去速度和剩余时间的占位行。压缩大块卡片间距，常用信息优先出现在首屏。

内容检查继续作为后台流程。用户界面集中表达结果及恢复操作；历史记录中的算法、摘要选择和清单管理入口纳入本版清理检查，数据兼容单独保留。

## 7. 确认面板、输入与反馈

### 7.1 统一面板

| 场景 | 内容与动作 |
| --- | --- |
| 下载到本地 | 所选文件列表、下载到、取消／下载 |
| 上传 | 本地项目列表、目标目录、同名处理、取消／上传 |
| 新建文件夹 | 标题、名称输入、取消／新建 |
| 重命名 | 名称输入、取消／确定 |
| 移到回收站 | 所选文件列表、取消／移到回收站 |

同类面板统一宽度、边距和按钮位置；列表内容随项目数量滚动。面板绑定确认时的网盘、账号、目录和项目。文件选择、保存位置使用系统面板。

重命名和新建共用输入反馈规范：提交时检查，错误字段红色描边，旁边提供简短可执行提示；编辑后更新反馈。Return 执行适用的默认动作，Escape 取消；删除键盘行为按破坏性操作独立确认。

普通任务只保留一层业务确认面板。关闭后返回原页面。当前云端回收站恢复由对应网盘提供，因此继续保留精简删除确认。

### 7.2 加载、结果与错误

- 加载文字统一“加载中”；已有内容刷新时保持列表可见，并在局部表达活动。
- 空目录、空任务列表和搜索空结果分别提供与当前场景相符的简短内容。
- 成功提示轻量展示，最长 10 秒自动消失，支持手动关闭。
- 需要用户处理的错误留在对应位置，提供重试、重新登录或重新选择文件等动作；任务失败同时保留在任务记录中。
- 提示说明发生的情况和下一步操作，名称使用【】引用，操作文案保持简短。
- 登录失效只在所属网盘显示状态，两家账号各自处理。

## 8. 设置、视觉和可访问性

### 8.1 设置与账号

沿用传输、网盘、网络、账号四类。常用选项直接展示，专业连接参数集中在高级区域，说明表达实际作用及必要限制。任务临时选择放在对应操作面板。

两家账号使用相同的字段顺序和动作位置：账号名称、状态、登录或退出。设置提供 `⌘,` 入口，恢复上次使用的分类。代理等已有能力和账号数据继续兼容。

### 8.2 全局视觉规则

- 应用自有界面使用不透明实色背景、轻分隔线和紧凑布局。按用户要求，不使用 Liquid Glass、背景透出和大胶囊容器，macOS 26 下同样执行。
- 使用系统字体、语义颜色与强调色，跟随浅色、深色、增加对比度等系统选项。
- 界面层级统一：页面标题、项目名称、辅助信息；数据数字按需要使用等宽数字。
- 控件尺寸、圆角、分隔线、菜单与焦点使用系统规则。品牌图标只承担网盘身份识别。
- 主内容采用紧凑列表，确认和设置采用清晰分组；重复背景、冗余卡片和空白合并整理。
- 成功、等待和失败同时使用文字或图标表达，颜色作为辅助。
- 键盘支持搜索、设置、目录导航、选择和面板确认；VoiceOver 可读出控件名称、状态与操作范围。

## 9. 可以简化的实现

| 当前实现 | 简化方向 | 完成条件 |
| --- | --- | --- |
| 表头宽度、行尾宽度、独立列拖动计算 | 系统树形表格共享列模型 | 异步目录及全部既有列表交互通过原型验证 |
| 上传与下载各自组织任务行 | 共用展示结构，分别提供业务状态 | 两种方向的状态、操作和批量范围一致 |
| 多处大卡片与重复统计 | 共用紧凑详情结构 | 主要信息清楚，长路径与大批次可查看 |
| 多个面板的间距、按钮和字段反馈 | 按同类场景复用布局与输入反馈 | 保留每种操作的目标和确认语义 |
| 分散的阶段文案与通知 | 统一用户状态映射和反馈规则 | 成功、收尾、失败、取消与重试均对应真实状态 |
| 独立背景、圆角和焦点修饰 | 使用实色容器与标准控件 | 浅深色、窗口缩放和可访问性均通过 |

复用现有业务状态，展示层读取对应数据。迁移按替代实现、调用方切换、验证、清理的顺序进行。资源收益以实测为准：使用同一构建模式、设备、目录和任务样本比较包体、空闲 CPU、内存、浏览及传输表现。

## 10. 实施顺序与验收口径

1. 固定 4.0 的登录、数据、传输和资源基线；验证原生树形表格可行性，明确迁移范围。
2. 统一主窗口、导航高亮、文件列表、工具栏和搜索。
3. 统一传输行和任务详情，精简内部阶段展示。
4. 整理确认面板、设置、反馈和可访问性，清理已替代的展示实现。
5. 使用实际 App 完成两家网盘回归、资源对比和本机替换。

| 验收领域 | 产品结果 |
| --- | --- |
| 导航与范围 | 当前页面和网盘范围清楚，分类数量及批量命令对应当前可见对象 |
| 文件管理 | 浏览、勾选、排序、列宽、拖放、重命名、创建和删除准确，父子层级一致 |
| 上传下载 | 两家均可完成文件与目录传输，内容一致性规则持续有效 |
| 任务展示 | 上传下载信息层级统一，收尾与完成语义准确，错误有明确处理入口 |
| 窗口与视觉 | 实色界面；普通、半屏及全屏下操作可达，浅深色文字和状态清晰 |
| 键盘与可访问性 | 焦点可辨认，主要路径可通过键盘和 VoiceOver 使用 |
| 升级与轻量 | 旧登录、任务和设置可继续使用，包体及资源变化有可比实测记录 |

## 12. 方案复核

- 整体范围覆盖用户提出的所有界面领域，继承 4.0 文件管理和传输能力。
- 系统树形表格采用原型验证后迁移，重点核对分享文件树和异步展开的调用关系。
- 较浅的网盘范围高亮保留用户既有选择，视觉强度在实际原型中验证。
- “正在完成”作为用户状态，真实任务阶段仍决定成功与失败，内容检查继续运行。
- 当前交付为方案文档。实现按[技术方案](architecture.md)、[任务清单](tasks.md)和[测试用例](test-cases.md)推进，文档审查见 [Review](review.md)。
