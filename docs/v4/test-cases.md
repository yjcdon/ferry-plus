# Ferry Plus 4.0 测试用例清单

状态：验收进行中；本文件定义通过标准，实际结果见 [执行记录](test-execution.md)，不得把组内部分通过当成整组通过。日期：2026-10-28。

依据：[产品方案](product-proposal.md)、[技术方案](architecture.md)、[任务清单](tasks.md)。组内不同场景分别记录结果；“两家”表示百度和夸克各执行一次，不能以其中一家代替另一家。

## 1. 验证方式与样本

- **UI**：Agent 操作实际构建的 App，记录页面、动作及结果；不通过 CLI 直接调用业务接口冒充界面验收。
- **受控**：现有测试文件／fixture 或临时样例模拟重复分页、迟到响应、会话变化等；与真实 UI 证据分开。默认不新增测试类。
- **静态／构建**：调用方检查、差异审查、受影响编译与现有相关测试，不能代替真实传输和 UI 验收。
- 使用现有两家登录。各建一处本轮专用云端测试目录，记录其账号与准确引用；删除只作用于该目录内明确创建的内容，不清空回收站。本地清理仅移到废纸篓。
- 复用一套样本：零字节文件、中文长名称小文件、同名不同内容文件、多层目录含空目录，以及大于该测试账号实际分片阈值且足够小的文件。先确认阈值，不能仅按文件大小宣称已分片；不进行多 GiB 长测。
- 两家各一次正常上传→完整回读→从文件页下载→本地全文件摘要对比；尽量复用这批样本覆盖其余 UI。异常分页用受控样例，不为凑分页在真实网盘创建大量文件。
- 进入 4.0 前记录原任务和设置基线；两次比对之间用户主动修改的数据单独说明，不把用户清理误判回归。不导出 Keychain 凭据。
- 锁屏、系统权限或登录挑战无法自动处理时记录具体阻塞，向用户说明需要的实际动作；不能将工具不可点击判为 App 崩溃。

| TC-10 | 受控两家：目录跨多页，目标名称仅在最后一页；随后搜索和全选 | 每层完整读取后可搜到该层最后一页；根级搜索及全选覆盖全部匹配；仅展开时请求对应子目录，初始不全树递归 |
| TC-11 | 受控：百度重复页、缺失身份／文件类型／文件大小、负数大小；夸克重复 ID／总数矛盾；第二页错误 | 报告不完整／响应异常，不返回半份成功列表；真实 0 字节合法；刷新失败保留旧快照并标记，首次失败不展示为空目录 |
| TC-12 | 受控＋UI：慢根／子节点请求期间换目录／网盘／会话或收起节点，刷新途中再次失效；已记住目录被删除，百度同路径重建且 fsID 改变 | 迟到根／子节点响应不覆盖新树；新失效不被旧响应清除；旧目录引用报失效，不把新同名对象当旧对象，不静默改上传目标 |

## 3. 执行记录和通过规则

实施时为每组记录：用例号、百度／夸克或通用、前置数据、源码提交、App 构建标识、执行方式、实际结果、证据路径、缺陷编号。状态使用“未执行／通过／失败／阻塞”；本轮不适用的子场景必须说明依据，不静默跳过。

40 个组用于覆盖关系，不是 40 次独立大文件测试。可以一轮正常传输验证多个组；异常与重复分页优先受控验证，实际 UI 的点击、布局、面板和焦点必须真实操作。失败后修复并重测受影响组，不无条件重复整个清单。

全部适用场景有明确结果且无阻塞核心流程的问题，才能记录本版验收完成。未执行、阻塞或已知缺陷不能用“基本通过”掩盖。
