# Ferry Plus 4.0 设计 Review

日期：2026-10-28。范围：产品方案、技术方案、任务清单、测试用例；源码参照 `main@63ff505`。

设计结论：文档已完成一致性审查，发现的两项 P2 设计问题已修订。随后用户已授权实施，代码审查与实际 App 验收正在推进；最终验收尚未完成。

## 1. 审查方法

- 主代理核对现有主窗口、菜单、账号会话、文件列表、上传下载确认、云端结果定位及分页接口。
- 按用户本次 Review 要求，使用只读审查子代理独立核对四份文档与相关源码；主代理复核其发现后修订文档。
- 核对产品功能 F-01～F-08、实施任务 T01～T14、测试用例组 TC-01～TC-40 的映射；检查本地文档链接与差异格式。
- 未执行真实账号写入、构建、测试、提交、推送或发布。

## 2. 发现与修订

| 编号／等级 | 发现与依据 | 修订结果 | 验证落点 |
| --- | --- | --- | --- |
| R-01 / P2 | 技术稿仅要求恢复时按账号读取目录；`BaiduNetdisk.listDirectory` 忽略 fsID，只按路径读取，同路径删除重建可能被当作原目录 | 文件工作区明确复用 `UploadEnvironment.listDirectory` 和既有 `checkedBaiduDirectoryPath` 身份核对；旧引用失效需重新选择，不增加一套检查接口 | 技术方案 §4.1；T03／T04；TC-12 增加同路径重建、fsID 改变 |
| R-02 / P2 | 技术稿将目录递归取消统一描述为不创建任务；实际普通目录下载先持久化任务再由 JobCoordinator 枚举，只有 JSON 清单在确认流程内提前枚举 | 分别定义入队前取消与入队后处理，保留原编排顺序，不为前端改版重复枚举或删除已有任务记录 | 技术方案 §5.2；T07；TC-23 区分两个阶段 |
| R-03 / 补全 | 上传终态除了完成、失败、取消，还包括 skipped（跳过） | 刷新规则列全四种终态；初始化快照不当成新完成事件，进度更新不重复刷新 | 技术方案 §6.1；T09；TC-35 |
| R-04 / 边界说明 | 夸克历史结果可能只有 fid，不能还原完整祖先路径 | 产品及技术文档统一展示已知节点和未知祖先；只有已知父级时可返回上级，不全盘扫描、不伪造路径 | 产品方案 §5.1；技术方案 §4.3；TC-33 |

R-01、R-02 的问题关闭指设计已修正，后续代码仍须按对应用例验证；不能据此宣称风险已经在软件中消除。

## 4. 后续实施边界

按用户最新要求，4.0 首版改为复用当前下载页的 List／FileTreeRow 展开勾选列表。主代理已重新核对产品、技术、任务与用例：移除 Table 和 Command／Shift 行选择要求，补齐展开不改变上传目标、节点准确父目录、父子去重、搜索及收起后的隐藏勾选清理。此前只读子代理审查发生在本次展示约定调整前，本次同步由主代理完成。

列表深层缩进的列对齐、勾选继承和拖放高亮仍需用构建 App 验证；本文不把现有组件可复用视为 4.0 已经实测。

最新补充已由主代理对照当前调用方复核：技术方案 S-01～S-12 明确旧路由、弹窗联动、重复浏览状态、草稿和最近上传目录恢复链的替代及清理条件；T11 承接逐项清理，TC-39 补充原能力保留核对。AppModel.createUploadDirectory、共享 FileTree、结果查询、账号／会话冻结和传输校验均列为保留职责，不能因为移除旧页面连带删除。清单仍为待实施设计，没有删除实际源码。

保留现有平台、账号、任务格式、固定签名和 Homebrew 分发；不增加夸克安全覆盖、极端恢复、全盘搜索、睡眠唤醒或资源专项。各测试实际结果见实施记录，发布和本机正式版更新仍需后续明确授权。

## 5. 实施阶段代码审查

主代理及两个只读子代理已检查文件浏览状态、确认面板、菜单焦点和工作区接线。以下问题已在源码修复并通过整体 App 编译，实际 UI 回归继续进行。

| 问题 | 修复 |
| --- | --- |
| 新建弹窗确认时读取可变目录，可能在换会话后写入新目标 | 打开弹窗即冻结原 DirectoryContext，提交核对账号、会话和目录 |
| 刷新中旧树交互和迟到子节点可能复活旧勾选 | 禁用刷新中的旧树交互，按树代次拒绝旧请求，恢复前读取最新有效选择 |
| 首次 Command-U 早于目录加载会丢请求，空命令还会清空原拖入草稿 | 保留上传意图等目录可用再展示，保留已有本地文件；取消同时清意图 |
| 页面切换共享局部提示，百度可能显示夸克的目录操作结果 | 文件页按网盘赋予独立 SwiftUI 身份，浏览状态仍按网盘保留 |
| 云端结果只传目录，遗漏已有准确文件引用 | 详情请求冻结可选文件引用，传给工作区并在读取后定位 |
| 确认互斥遗漏任务移除／保留依据流程 | 统一纳入主窗口确认可用条件，已有流程结束后再消费导航请求 |
| 极小任务首次可见即终态可能漏刷新 | 对本次新增任务的首个终态快照补充目录失效，不对历史完成任务逐个刷新 |

未发现明确的强引用环或无限刷新调用链。该结论来自源码审查，不声称已完成资源专项。临时 harness 对实际 FileTree、DirectoryBrowserState 及百度目录身份核对执行 12 项受控检查全部通过；其账号、读取闭包和偏好存储替身边界见本地 JSON，不把受控测试当成真实账号 UI 证据。

## 6. 普通下载简化复核

用户在实际使用后明确要求不展示复杂校验配置。设计与代码已改为文件、保存位置和下载按钮；删除确认页中的手动摘要／历史版本／JSON 模式及关联状态，技术清理新增 S-13，TC-20～22 更新为简洁确认、后台检查和旧数据兼容。旧入队前 JSON 枚举分支随表单移除；正常下载只沿用入队后枚举。

后台 JobCoordinator 和下载引擎未因本次简化改动，旧任务的显式校验绑定和记录继续可读取。新普通下载不自动采信历史候选，也不为界面精简引入新校验框架。最新 App 已实际核对百度单文件与夸克目录确认，无校验配置；百度小文件经新确认下载后完整 SHA-256 一致。

## 7. 收尾 Review 修复

| 问题 | 修复及验证状态 |
| --- | --- |
| AppModel 分享入口只知道自己的 sheet，主窗口上传／下载确认或详情打开时仍可能由 Cmd-N／剪贴板另开分享 | 主窗口反馈实际占用，手动与自动分享使用同一条件；自动检测异步返回后再次核对；主窗口不反读反馈标记，避免关闭后自锁 |
| 待上传草稿存在时，从工具栏或行级上传入口传入空列表／另一批文件，提交后却清掉原草稿 | 唯一 presentUpload 入口合并草稿和本次文件，标准化后去重；确认内明确移除的文件按用户选择处理 |
| 文件／策略变化后，新预检任务启动前仍短暂沿用旧预检结果 | 保存预检所属请求，上传条件要求文件、策略和检查代次与当前请求一致 |
| 文件页仍注册最外层窗口 dropDestination，最终处理才拒绝，可能抢走内层拖放 | 最外层拖放仅注册在传输页；文件页保留自己的行与根目标。此改动移除结构冲突，Finder 正例仍需实际复测，不能宣称已确定全部根因 |

上述修复已通过整 App 构建及严格签名验证。恢复界面测试后的结果见 [执行记录](test-execution.md)。

恢复后实际发现重复 Command-U 会在取消上传确认后再次打开确认。工作区请求入口现拒绝已有弹窗期间的新浏览／上传命令；云端定位请求保留关闭详情后消费的能力。重建后复测：上传确认打开时再按 Command-U，取消一次即返回文件页，没有再次弹窗。

实际列表全选快捷键曾无效。现在提供唯一的系统编辑菜单全选入口：文本焦点交给原生文本响应者，文件／传输列表按当前可见范围选择；确认面板占用时不提供后台列表操作。剪切、拷贝、粘贴和删除继续转发到原生响应链，不自行处理剪贴板。重建后的文件与传输范围、弹窗隔离及文本复制／剪切／粘贴均已实际操作。没有目标时编辑菜单的这些操作仍可能显示可点击，执行时由原生响应者决定是否处理；这是当前菜单呈现的限制。新增接线不持有窗口、响应者或后台任务，未发现明确引用环。

## 8. 提示文案复核

上传、下载、文件删除和校验提示已按用户语言精简。代码复核确认仅在文件校验通过时显示“文件内容一致”，未知结果不会显示为一致；删除确认显示待删除项目及回收站操作。

## 9. 后台任务与资源复核

复查工作区刷新、上传观察和确认面板的任务生命周期：目录刷新由上传终态变化触发；目录加载闭包弱持有状态，上传观察在结束时移除，面板关闭时释放文件访问权限和选择器。未发现明确的强引用环、死循环或按每次传输进度刷新目录。此结果来自源码审查，不代表资源占用专项测试。

最新搜索焦点和删除提示改动经源码复核：文件与传输搜索仍分别绑定各自状态，搜索框卸载时解除代理；删除操作仍区分成功和未确认项。未发现明确回归或新的循环、强引用问题；拖放及异常场景仍以执行记录为准。

拖放实现独立复核未发现确定的重复接收、跨账号写入或资源泄漏。文件行与父容器的事件传递仍需要真实 Finder 拖放验证；文件行接收回调在状态切换时可能报告已接收而未打开确认，其是否可触发尚未验证。

按用户最新要求，删除确认不再展示传输影响，相关的任务匹配与目录遍历已移除。
