# Ferry Drive 5.0 任务清单

日期为 2026-11-10。依据 [产品方案](product-proposal.md) 和 [技术方案](architecture.md)，对应 [测试用例](test-cases.md)。实施和验收状态见[测试执行记录](test-execution.md)。

## 1. 执行与完成规则

目标为一套 MyGo 原生 UI 与 Go 业务核心，交付 macOS 14+ Apple Silicon、Windows 10 和 Windows 11 x64。Windows 10 最低构建暂按 1809（17763）验证，并覆盖 22H2。沿用当前网盘登录和 4.2.0 最终行为，5.0 使用独立数据，直接下载安装。

第一阶段测试在 Mac 上执行，覆盖共享逻辑、原生界面、双网盘闭环、持久化及安装。Windows 目标在 Mac 上执行编译与打包检查，Windows 系统运行、登录及交互用例记为“第二阶段待验证”。第二阶段具备 Windows 环境后执行 Windows 10/11 用例并修复差异。以下任务依赖在第一阶段按 Mac 实现和适用验证解除，Windows 运行待验证不阻塞第一阶段。

任务按依赖推进，独立模块可以并行实现。任务状态区分“实现完成”和“集成验收通过”。基础模块通过接口契约测试、平台适配器探针和构建后，可标记实现完成并解除后续开发依赖；产品入口及跨模块用例随集成任务验收。集成验收通过要求实际调用入口、对应完整测试结果及文档同步。测试环境或真实账号缺失时记录待验证，完整交付以 T18 为准。

每项实现保留对应 F 功能编号与 C 用例编号，新增代码延续既有业务职责。已替代入口在全部调用方迁移、行为验证后清理。具体提交、发布和上传按后续实施授权执行。四份文档的本轮审查修订见 [Review 记录](architecture.md#9-四份文档-review-记录)。

## 4. 执行记录

实施开始后在版本目录维护执行记录，每个任务记录阶段、状态、变更提交、用例及证据路径。每个用例按阶段、平台和网盘分别记录，结果使用待执行、通过、失败、阻塞、不适用，并为不适用注明依据。Windows 运行项在第一阶段记录为“第二阶段待验证”，不计入第一阶段失败或阻塞。初次方案 Review 记录放在技术方案末尾；实现 Review 随实施记录保存。

真实网盘写入只使用专用样本目录，保留对象 ID 及摘要。已失败或待验证用例保留原始结果，修复后追加复测。用户已经排除的 4.x 数据迁移与应用内更新不加入实施任务。
