# Ferry Drive 5.0 产品方案

方案已完成文档 Review，实施待启动。5.0 使用 MyGo 原生 UI，同时提供 macOS 与 Windows 客户端，以当前版本的功能、界面展示和交互为迁移基准。修订结果见 [Review 记录](architecture.md#9-四份文档-review-记录)。

## 1. 方案定位与目的

Ferry Drive 5.0 承接 Ferry Plus 的双网盘文件管理与传输能力。使用者仍通过一个桌面应用登录百度、夸克，浏览文件、上传下载并管理传输任务。

核心目的是让 Windows 用户也能使用 Ferry Drive，同时让现有 Mac 用户用熟悉的界面和操作完成相同任务。

采用一套跨平台原生界面承载相同的功能结构，业务流程沿用当前实现，系统窗口与文件操作按所在平台适配。保持已有的紧凑、实色界面和简洁反馈。

## 2. 基准与范围

### 2.1 当前行为基准

以本次方案编写时的 4.2.0 源码 `449de5a5faf78f2fa8753d99877e84b12235f0fa` 为基准。需求依据依次为本次用户确认、该提交实际实现、对应实施记录与历史方案。历史方案中已经被后续实现替代的描述，以当前实现为准。

当前功能说明见 [README](../../README.md)，界面演进见 [4.1.3 实施方案](../v4.1.3/architecture.md) 和 [更新记录](../../CHANGELOG.md)。以下行为属于迁移基准。

- 选择文件或文件夹后直接上传，拖到空白处上传到当前目录，拖到文件夹上传到该目录，同名默认保留两份。
- 行高亮与勾选框共用选中集合，支持连续和不连续多选，批量命令及底部数量使用同一范围。
- 空白处或空目录右键新建文件夹，创建后行内命名，重命名也在列表内完成。
- 上传、下载详情采用当前精简布局，账号名称集中在账号区域，成功操作主要由列表和任务状态变化表达。
- 未登录页面保持当前简洁展示和可用的目录导航。

### 2.2 交付边界

| 项目 | 5.0 约定 |
| --- | --- |
| 产品版本 | Ferry Drive 5.0 |
| 界面 | 主窗口、文件页、传输页、设置及业务弹窗使用 MyGo 原生 UI |
| 登录 | 沿用当前网盘官方网页登录、凭据提取校验与恢复流程，百度保留现有 Cookie 登录补充入口 |
| 安装 | 用户下载对应平台的最新安装包安装 |
| 首次使用 | 重新登录、选择本地目录并创建任务，采用 5.0 独立本地数据 |
| 历史范围 | 4.x 登录、设置、任务及未完成传输的数据迁移不在本次范围 |
| 更新范围 | 应用内自动检查、下载和替换更新不在本次范围 |
| 版本信息 | 在关于窗口展示 5.0 版本号，设置保留传输、网盘、网络、账号四类 |
| 发布平台 | macOS 14+ Apple Silicon；Windows 10 / Windows 11 x64，Windows 10 最低构建按 1809（17763）制定验收基线 |

官方登录页是现有登录流程的一部分。登录之外的产品页面均由原生组件呈现。5.0 自己创建的设置、账号和任务需要保存，并在再次启动后按既有业务规则恢复。

## 3. 核心使用流程

1. 用户安装应用，在账号入口登录百度或夸克。两家账号分别管理，某一家异常时在对应账号区域恢复。
2. 用户在侧边栏选择网盘，通过目录展开、进入、路径导航、当前目录搜索定位文件。页面保留对应网盘的浏览位置与有效选择。
3. 用户选择本地文件或拖入文件发起上传，或勾选云端文件确认下载位置后下载。分享链接沿用粘贴、识别提取码、解析、选择文件并下载的流程。
4. 用户在传输页按网盘、方向、状态与名称筛选，暂停、继续或重试任务，并在详情查看结果与定位文件。
5. 任务完成后，用户查看本地或云端结果。发生失败时，从对应字段、任务或账号入口采取现有恢复动作。

## 4. 功能与展示要求

| 编号 | 功能 | 5.0 迁移要求 |
| --- | --- | --- |
| F-01 | 主窗口与导航 | 保留左侧导航、中间内容、可开关右侧详情。保留网盘范围与传输分类的高亮区别、查看全部、分栏调宽、窄窗收纳及窗口偏好恢复。 |
| F-02 | 网盘账号与登录 | 百度、夸克各一个同时登录账号。沿用官方登录页、临时登录会话、Cookie 检查、账号校验、退出及失效恢复。保持百度 Cookie 补充登录的触发条件和文案。 |
| F-03 | 文件浏览与选择 | 保留名称、修改日期、大小三列，目录展开、双击进入、路径导航、当前目录搜索、列头排序、列宽调整、勾选与多选。父目录包含的子项按既有规则去重。 |
| F-04 | 文件管理 | 保留右键新建文件夹、行内命名和重命名、批量移入网盘回收站及确认。新建成功后自动聚焦名称，取消编辑保留已创建目录的默认名称，错误就近显示。 |
| F-05 | 本地上传 | 文件与文件夹选择、拖放、后台扫描、目录结构、分片、限速、暂停继续、失败重试与内容检查均沿用当前规则。选择完成即入队，同名默认保留两份。无明确目录的入口继续引导选择目标。 |
| F-06 | 文件及分享下载 | 保留账号内文件下载、双网盘分享解析和提取码识别、文件选择、下载位置确认、目录结构、分片续传与后台内容检查。按原规则处理转存及清理。 |
| F-07 | 传输列表与详情 | 保留网盘、上传下载方向、全部／进行中／已完成／失败分类、搜索和批量操作。数量、统计与操作目标一致。保留当前详情字段、分页、定位、源文件重选和按状态启用的恢复动作。 |
| F-08 | 设置与反馈 | 保留传输、网盘、网络、账号设置及当前默认值和有效范围。保持系统下载目录、自选目录、并发、限速、分片、剪贴板检测、转存清理及代理。字段、任务、账号分别承接对应异常。 |
| F-09 | 桌面集成与安装 | 保留文件选择、拖放、剪贴板、文件定位、通知和任务生命周期行为。提供两端安装包、版本信息和 5.0 数据持久化。 |

F-07 中的“正在完成”继续包含必要的合并、校验或发布处理，传输字节达到总量后，依据实际结果进入已完成。移除记录、删除本地文件、移入云端回收站保持各自的操作名称与影响范围。任务创建后保持当前文件页面，进入传输页时按现有筛选决定是否选中新任务。

上传保留“优先上传”和“取消上传”。优先上传调整尚未执行批次的顺序，取消上传保留已成功的云端内容，在途提交完成核对后再决定是否允许移除记录。上传、下载及校验回读实际执行期间保留防闲置休眠能力，全部暂停、结束或退出时释放。

## 5. 界面和交互一致性

### 5.1 对齐方式

以当前应用的代表页面和状态建立对照，覆盖双网盘文件页、上传下载混合列表、上传与下载详情、分享链接、下载确认、删除确认、行内编辑和四类设置。相同内容窗口尺寸、主题和样本数据下，对比区域位置、列顺序、文字、字号层级、间距、图标语义、状态反馈和操作路径。

应用绘制区域沿用实色表面、紧凑列表和轻分隔线。名称长时保留当前省略和查看完整内容的方式，日期、大小和进度沿用现有格式。浅色、深色、焦点、禁用和错误状态一并对齐。

当前目录搜索与任务搜索保持各自范围。刷新、排序、展开和异步结果返回后，按当前规则恢复有效选择与位置。键盘、工具栏和右键菜单调用同一操作规则。

### 5.2 必要的平台适配

| 场景 | macOS | Windows |
| --- | --- | --- |
| 窗口 | 系统窗口按钮、菜单及全屏习惯 | 系统窗口按钮、缩放及最大化习惯 |
| 搜索及常用组合键 | 沿用 Command 组合键 | 对应 Ctrl 组合键，按文本输入和系统保留键检查冲突 |
| 文件多选 | Shift 连选、Command 多选 | Shift 连选、Ctrl 多选 |
| 行内重命名 | 保留现有触发方式 | 右键操作及 F2，保留编辑提交和取消语义 |
| 本地定位 | 在 Finder 中显示 | 在文件资源管理器中显示 |
| 文件选择及通知 | 系统选择器、macOS 通知 | 系统选择器、Windows 通知 |

布局、信息结构和业务流程以同一套设计为准。系统字体度量、窗口装饰、选择器外观及快捷键修饰键允许随平台变化。遇到框架能力差异时记录具体影响和处理方案，尤其核对文件与文件夹混合选择、拖放目标、中文输入和多选行为。

下载到 Windows 时，系统无法创建的文件名按具体文件显示失败原因，其他文件按任务规则继续处理。可创建的同名文件沿用保留两份的落盘行为，详情定位使用实际保存位置。

## 6. 产品验收口径

验收分两阶段。第一阶段在 Mac 上完成原生界面、两家网盘业务、交互对照及安装验收；Windows 运行用例统一安排到第二阶段，不作为第一阶段完成的前置条件。第一阶段保留 Windows 10/11 的实现目标，并在 Mac 上检查 Windows 目标编译与安装包生成。第二阶段具备 Windows 环境后，再完成 Windows 的实际运行验收。

下列结果按当前阶段对应的平台验收，跨平台整体完成以第二阶段结束为准。

- F-01 至 F-09 在两端均有可用入口，按同一业务规则完成操作。明确排除的旧数据迁移与应用内更新按本方案边界验收。
- 界面与当前基准逐页、逐状态对照。差异限定为本方案列明的平台适配，其他差异在交付前复核。
- 两家真实账号分别完成登录、浏览、文件管理、上传、账号内下载和分享下载。内容校验、部分失败及恢复动作对应真实结果。
- 选择器确认、拖放、行内编辑、筛选、批量操作、搜索与详情定位的作用对象准确，账号或目录变化后操作保持正确边界。
- 5.0 重启后恢复自身设置、账号及任务。正常退出、中断恢复和源文件重选满足现有任务语义。
- 浅深色、窄窗口、长中文文件名、较大目录、中文输入法、键盘操作及两端辅助功能完成实际运行验收。
- 从对应安装包完成安装和启动。Windows 的运行结果在 Windows 环境验证。

## 7. 依赖与平台基线

网盘登录、分享解析及传输依赖两家网盘现有服务和用户账号权限。Windows 官方网页登录依赖 WebView2 Runtime，安装交付时检查并提供系统运行时安装路径。

Windows 10 支持是已确认需求。具体构建号暂采用 Windows 10 1809（17763，覆盖 LTSC 2019）作为最低验收基线，并覆盖 Windows 10 22H2 与 Windows 11；这是本方案对未指定构建号的实施假设。Windows 首发架构为 x64。T02 第一阶段完成 Mac 原型运行与 Windows 构建检查；第二阶段在最低 Windows 基线实际核对系统 API、渲染和登录运行时，发现限制时修正实现或提请复核范围。

执行安排见 [任务清单](tasks.md)，验收场景见 [测试用例](test-cases.md)。
