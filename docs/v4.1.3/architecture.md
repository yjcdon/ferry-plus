# 4.1.3 技术方案：直接上传

## 目标与产品依据

依据本次已确认交互：用户在百度或夸克的目标目录点击上传，系统选择器可多选文件和文件夹，确认即入队；拖到列表空白处上传到当前目录，拖到文件夹上传到该文件夹。取消原上传确认页，保持当前页面，传输列表展示进度。同名默认保留两份。文件列表空白处及空目录右键可新建文件夹，移除工具栏的新建文件夹按钮。

本版本收录已经完成的图标调整：下载使用 arrow.down（向下箭头），上传使用 icloud.and.arrow.up（云朵向上箭头）。版本由 4.1.2 升为 4.1.3。

## 现状与技术决策

MainView 已接收 DirectoryContext（包含账号、客户端会话和准确目录）；NetdiskOutlineView 已按投放位置区分当前目录与文件夹。原 UploadConfirmationView 在 sheet 中再打开 NSOpenPanel，并重复扫描、等待用户提交。

保留现有表格拖放与 UploadCoordinator 入队、后台扫描、冲突处理、上传和内容校验。以主窗口持有的轻量上传入口替代确认页，不新增上传执行引擎。

## 数据、生命周期与异常

- 用户打开选择器时冻结 DirectoryContext，确认后核对同一账号和客户端会话；切换会话时提示重新选择上传位置。
- 选择器附着主窗口，主窗口持有 presenter；取消不创建任务。入队期间保持源文件 security-scoped 访问，书签创建完成后释放。
- URL 在入口校验为本地文件并按标准路径去重，入队固定使用 keepBoth（同名保留两份）。原任务保存的其他策略继续可恢复。
- 扫描由既有后台任务完成，问题进入任务失败状态。原页面的容量预估只供预检使用，本次移除这份预估；实际容量不足沿用网盘上传接口错误与任务重试机制，不承诺容量预留。
- 传输页等缺少明确目录的拖入仍保留已有待选目标流程；确定目标后直接入队。
- 确认弹窗、下载、删除、重命名和现有内容校验不受本次流程调整影响。

- 行内编辑按回车或离开字段提交，Esc 保留已创建目录的默认名称；错误保留输入并就近提示，提交期间禁止重复提交。编辑只绑定准确引用，切换目录结束编辑。
- 指定文件夹目标解析失败时拒绝投放；只有空白投放使用当前目录，避免目标悄悄变化。
- 目录扫描先校验根项目，再按真实文件系统根计算子路径，兼容 /tmp、/var 等祖先路径别名。

## 测试与 Review

执行 Release 构建、相关上传包测试；安装最新 4.1.3 并通过 computer-use 验证系统选择器、取消、双网盘上传及目录刷新、拖放目标与同名行为。记录实际覆盖与待测项，不以编译替代界面验收。最终检查窗口/任务生命周期、全部入口和旧引用，记录本地提交。

- 点击新建立即显示【创建中】；默认名基于完整目录快照选择。创建回执直接插入现有树并编辑，省去创建前后重复列目录和整树刷新；同名冲突由网盘返回，保留已有文件夹。
