# 4.2.0 任务清单

按以下顺序实施。功能范围见[技术方案](architecture.md)，用例编号见[测试清单](test-cases.md)。

- [x] T1 构建基线。统一两种构建入口的内部编号、框架嵌入及签名策略。在现有 Command Line Tools 环境构建可启动的 A、B 两个独立签名版本，B 的内部版本号更高。验收 C1。
- [ ] T2 测试发布源。建立独立测试清单，配置更新密钥，打包并验证 B。验证清单与安装包可读取、签名可校验，供 T3 使用。
- [ ] T3 更新体验。接入共享控制器、应用菜单、每日检查及设置开关，显示本次更新说明和下载进度。用 A 实际替换到 B，验收 C2 至 C5。
- [ ] T4 安装时机。接入传输状态和异步退出，验证推迟安装、保存和重启后的恢复。验收 C6、C7。
- [ ] T5 正式发布流程。统一生成说明、签名清单、Release ZIP、摘要及 Cask，处理预发布、失败重试和撤回。验收 C8。
- [ ] T6 渠道验收。分别从 GitHub ZIP 和 Cask 安装后升级，记录版本、签名、资源增量和实际结果。同步 README、构建指南和 CHANGELOG 中的首次升级方式。验收 C9、C10 后发布。

T1 已通过本机 Release 编译、框架嵌入与深度签名检查。Xcode 工程已做结构检查，当前机器使用 Command Line Tools，工程构建及 macOS 14 实机验证留待对应环境。A/B 实际替换记录随 T3 补充。
