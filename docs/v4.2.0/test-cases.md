# 4.2.0 测试用例清单

状态均为待执行。A、B 为带更新器的相邻测试构建。使用隔离的 GitHub 测试清单、测试账号与任务目录。记录实际系统、版本、安装路径及结果。

| 用例 | 操作 | 通过条件 |
| --- | --- | --- |
| C1 构建 | 分别通过命令行和工程构建，解压 ZIP 后启动；尝试以旧编号或临时签名发布 | 同版编号一致，框架可加载，错误配置在发布前拦截 |
| C2 正常升级 | A 查到 B，查看说明、下载、确认重启 | 与 GitHub 说明一致，原路径运行 B，仅有一个应用实例，再查显示已是最新 |
| C3 检查偏好 | 手动查同版、旧版和新版；关闭自动检查并重启，再开启，使用测试时钟验证每日调度 | 仅更高兼容版本可安装；开关持久化，关闭时仍可手动查 |
| C4 下载控制 | 选择稍后、下载中断网、恢复后重试 | 旧版可用，失败后可重试并成功安装，后台无新版无弹窗 |
| C5 安装保护 | 分别篡改清单、替换 ZIP、取消写入授权 | 安装被阻止，原包仍可启动；恢复有效签名与权限后可升级 |
| C6 活跃传输 | 上传、下载、校验期间分别请求安装；更新准备就绪时加入新任务 | 活跃任务继续，未被重启打断；空闲后经用户确认只安装一次 |
| C7 数据保留 | 准备两个登录账号、非默认设置、暂停和排队任务，升级后打开网盘并恢复任务 | 登录可用，同一应用签名身份下沿用已有钥匙串授权；路径、偏好、传输记录正确，恢复任务后内容正确 |
| C8 发布故障 | 发布测试版、模拟 ZIP 缺失与上传后清单发布失败，恢复后重试，并演练撤回 | 正式清单仅指向已验证的正式包；重试产物摘要一致，撤回后旧客户端不再收到该版本 |
| C9 渠道迁移 | 对 GitHub 与 Cask 两种来源分别从 4.1.4 安装接入测试源的候选 A，再升级到同源 B；对 Cask 安装执行卸载验证 | 首跳通过原渠道完成，第二跳在应用内完成；Cask 可正常卸载，测试源仅用于验收构建 |
| C10 兼容与占用 | 在 macOS 14 与当前使用系统上走一次完整更新；同机同状态对比 4.1.4 和新版 | 两个系统都能启动及更新；记录 ZIP、安装体积和空闲内存差值，按原项目约 100 MB 的目标评估 |
